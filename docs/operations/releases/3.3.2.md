# SpringSuite 3.3.2

## Module deployment safety

- `assembleDeploy` now includes only signed module JARs for the current SpringSuite version.
- Historical JARs left in module build directories are no longer copied into deployment payloads.
- `verifyDeployLayout` requires exactly three runtime module JARs, validates their declared version and rejects duplicate `SpringSuite-Module` IDs.
- Module bootstrap reads `SpringSuite-Module` and `SpringSuite-Module-Version` from every external JAR before constructing the class loader.
- Duplicate module IDs, missing module IDs and missing module versions now fail startup with an explicit diagnostic instead of relying on classpath order.
- `SuiteModuleRegistry` performs a second duplicate-ID check after `ServiceLoader` discovery to prevent silent module replacement.

## Live reconciliation

Deploying 3.3.2 from a manifest-based transaction removes module JARs that were listed by the previous deployment but are absent from the 3.3.2 payload. This reconciles stale 3.3.0 and 3.3.1 module artifacts without deleting user-preserved roots.
